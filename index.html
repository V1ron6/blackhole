No cookies, no history

Off by default, every launch. Need to stay logged in for something — a CTF target, say? Session Manager turns it on for that session only, and Clear Session always turns it back off.

Ads and trackers blocked

Filtered at the network layer before a request ever goes out — not a cosmetic content-blocker running after the fact.

Cert errors never bypassed

Strict mode blocks plain HTTP outright. CTF mode allows it for lab targets that only serve HTTP — but a broken certificate stops the load either way, no exceptions.

Why a mode system

Most browsers give you everything at once, or nothing at all. Blackhole scales with what you're actually doing.

BASIC

Browsing something ordinary. No clutter, no extra tools in the way — just a fast, private, ad-free browser.

INTERMEDIATE

Testing an API you're building. One tool unlocks: a request builder, so you're not switching apps to hit an endpoint.

ADVANCE

Debugging a site or doing lightweight recon. 18 tools open up — headers, storage, TLS, JS console, the encode/decode kit.

BYTEBANDIT

Working a CTF or an authorized pentest. The full set — SSH, port scanner, directory buster, WHOIS/DNS, TOTP — all in one place.

Every mode resets to Basic when you press Clear Session. Nothing stays unlocked by accident.

Questions

Is this on the Play Store?

No. It's distributed as a direct APK build. Some of the tools here — the port scanner and directory buster, especially — wouldn't clear Play Store's policy review even with the authorization gates built in, so direct distribution is the honest option rather than a workaround.

Does it collect any data?

No analytics, no crash reporting, no telemetry of any kind. The only permission the app requests is Internet, which it needs to browse at all.

What does "private by default" actually mean?

Cookies and local storage are off until you explicitly turn them on in Session Manager — useful for staying logged into something like a CTF target. Pressing Clear Session wipes whatever was stored and turns the toggle back off, so persistence never quietly outlives the session you turned it on for.

Do the recon tools go through my proxy?

Not yet. Regular browser traffic can route through Tor or Burp via the proxy setting, but the newer standalone tools (WHOIS, DNS, port scanner, directory buster, and the rest) currently connect directly. This is a known gap, not a design choice.

Can I build it myself?

Yes — it's a standard Gradle-based Android project. Clone it, open it in Android Studio or run ./gradlew assembleDebug from the command line, and you'll have a debug APK.
